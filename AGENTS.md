# Business — preferência de publicação

Complementa as instruções de `../AGENTS.md`.

- Preferência expressa pelo usuário em 12/09/2026: “no final sempre publique”. Ao concluir alterações solicitadas neste Business, publicar os arquivos de runtime do escopo após verificações, sem pedir outra confirmação de publicação.
- Preservar mudanças de outras frentes. Conferir baseline de produção, preparar backup recuperável, publicar somente os arquivos da tarefa e verificar o resultado real. Não declarar publicação apenas por testes locais ou upload.
- Se houver falha de validação, conflito de produção, acesso ausente ou necessidade de ação fora do escopo, informar o bloqueio; essa preferência não autoriza contornar proteções, alterar credenciais/permissões, executar migrações destrutivas ou publicar mudanças alheias.
- Pedidos somente de explicação, diagnóstico, revisão ou plano não autorizam alterações nem publicação. Respeitar uma instrução mais recente para não publicar.
- Publicação não autoriza commit, branch, tag, push ou PR; essas operações continuam exigindo solicitação específica.

## Convenção de atualização do GitHub

- Preferência expressa em 21/10/2026: “Update” sempre significa trazer as atualizações do GitHub para o projeto local (fetch/pull), preservando alterações locais. Não significa fazer commit ou push.
- Se as atualizações remotas conflitarem com alterações locais, informar o conflito antes de sobrescrever ou descartar qualquer trabalho.

## Preferência de interface

- Preferência expressa em 26/09/2026: em páginas extensas, organizar conteúdos por abas para evitar rolagem excessiva. Separar tarefas e detalhes relacionados, preservando filtros, links diretos e navegação por teclado.
